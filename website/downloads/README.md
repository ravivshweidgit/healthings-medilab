# APK files are published to the VPS — not stored in git.

Two APKs are served from `https://healthings.ai/downloads/`.

**This folder is not the Downloads page.** The page people read lives at
`/{lang}/downloads/` (generated by `website/scripts/gen-downloads-locales.mjs`) and
links to the binaries here. `/downloads/` itself redirects there, so the two never
have to fight over the same URL.

## Healthings app

Build locally:

```powershell
Set-Location app\android
.\gradlew.bat assembleRelease --no-build-cache
```

Then publish (from repo root):

```powershell
bash website/scripts/publish-apk.sh
# or on Windows: website\scripts\publish-apk.ps1
```

Output on server: `https://healthings.ai/downloads/healthings-medilab.apk`

## xDrip+ mirror (CareSens Air help topic)

`/{lang}/help/xdrip-caresens.html` sends CareSens Air users here for the bridge
app, so the file has to exist or that page has a dead button.

```powershell
website\scripts\fetch-xdrip.ps1
# or: bash website/scripts/fetch-xdrip.sh
```

This pulls the current release straight from
[NightscoutFoundation/xDrip](https://github.com/NightscoutFoundation/xDrip) and
writes `xdrip-plus.apk` plus `xdrip-plus-version.txt` (upstream URL, release tag,
sha256, date).

**Serve it unchanged.** xDrip+ is GPL-3.0, and mirroring the upstream build with
a link to the source is fine; repackaging or resigning it would make us the
distributor of a modified glucose app. Re-run the script every few months so the
mirror is not years behind upstream — the version note is how you check what is
live.

Output on server: `https://healthings.ai/downloads/xdrip-plus.apk`
