data survives Sync, mentors cite real numbers, and we have a repeatable test plan.

**Build order:** ship PART A–E (connect + verify) first on a live CareSens device.
PART G (manual low-corruption exclusions) ships **after** connection is confirmed working.

**Not in scope:** direct BLE to CareSens, SmartLog cloud, iOS HealthKit, prompt09 7-day
glucose overlay chart, prompt08 visceral+glucose pair card (defer).

## PART A — Fix glucose merge on every refetch (`useHealthData.ts`)

Mirror `ReviewService.fetchPeriodIntraday()` merge strategy:

```ts
import { mergeGlucoseTimePoints, loadCachedHealthMetrics } from '../services/healthMetricsCache';

// Inside refetch(), after HC fetch:
const cached = await loadCachedHealthMetrics();
const mergedRaw = mergeGlucoseTimePoints([
  metrics.glucose,           // Health Connect (authoritative on duplicate timestamp)
  cached?.glucose ?? [],     // includes prior CSV import
]);
const knownStarts = mergeCgmSessionStarts(
  cached?.cgmSessionStarts,
  undefined, // CSV sessions already in cache
);
applyMetrics(
  { glucose: mergedRaw, steps: metrics.steps, heartRate: metrics.heartRate },
  knownStarts,
);
```

Rules:
- **Duplicate timestamp:** HC wins (same as `mergeGlucoseCsvWins` for CSV-over-HC on import)
- **Persist merged raw** in `healthings:lastMetrics`, not HC-only
- **Bootstrap** from cache then refetch — unchanged order, but refetch must not shrink series
- Export `mergeGlucoseTimePoints` usage consistently; avoid duplicating merge logic in a third place

### Acceptance (merge)
- Import CSV → chart shows history → tap **Sync** → point count does **not** drop
- HC adds new points after CSV import → both sources visible on chart
- Mentor `todayMealGlucoseDetail` uses same merged series as chart

## PART G — Manual exclusion of corrupted low CGM windows (after connection works)

Automatic filters (warm-up, statistical noise) already drop bad days in code.
Users still need a way to **mark specific time ranges** as sensor corruption — e.g.
compression lows, adhesive failure, obvious false readings — without hiding real highs.

### Anti-cheat rule (hard requirement)

| Reading level | User can exclude? |
|---------------|-------------------|
| **All samples in range &lt; 65 mg/dL** | Yes — mark window as corrupted sensor data |
| **Any sample ≥ 65 mg/dL in range** | **No** — UI disabled; cannot save exclusion |

Rationale: excluding high spikes would let users hide post-meal glucose; only sub-65
windows are plausible sensor failure / compression artifact, not dietary cheating.

Threshold **65 mg/dL** is fixed in code (not user-configurable).

### UX (chart-driven)

1. Long-press or **Edit CGM** mode on `MetabolicChart` → drag/select a time range
2. App computes min/max in selection:
   - if `max < 65` → show **"Mark as sensor error"** confirm
   - if `max ≥ 65` → show disabled state: *"Only low corruption (&lt;65) can be removed"*
3. Excluded ranges stored locally; chart greys out segment; mentors/stats ignore those points
4. **Manage exclusions** list — view + undo (restore points to series)

```
┌──────────────────────────────────────────────┐
│  Glucose chart                    [ Edit ]   │
│  ~~grey band~~ = user-excluded corruption    │
├──────────────────────────────────────────────┤
│  Excluded windows (2)                        │
│  Jun 4 03:12–05:40  max 52  [ Undo ]         │
│  Jun 2 11:00–11:45  max 61  [ Undo ]         │
└──────────────────────────────────────────────┘
```

### Storage (`TargetService.ts` or `healthMetricsCache.ts`)

```ts
export type CgmManualExclusion = {
  id: string;
  startMs: number;
  endMs: number;
  maxMgDl: number;       // must be < 65 at creation time (validated)
  reason?: 'sensor_error'; // only allowed enum for now
  createdAt: string;     // ISO
};

const CGM_MANUAL_EXCLUSIONS_KEY = 'cgm_manual_exclusions';

export async function getCgmManualExclusions(): Promise<CgmManualExclusion[]>
export async function addCgmManualExclusion(e: CgmManualExclusion): Promise<void>
export async function removeCgmManualExclusion(id: string): Promise<void>
```

Apply exclusions in `prepareGlucoseSeries()` **after** warm-up + statistical filters:
drop any point whose timestamp falls inside an exclusion window.

Mentor context: append one line when exclusions active:
`USER-EXCLUDED SENSOR ERRORS: N windows (all peaks &lt;65 mg/dL) — do not cite those readings.`

### Acceptance (PART G)
- User can exclude a window where all readings &lt; 65; chart + mentor stats update
- Selection spanning any reading ≥ 65 → action blocked with clear message
- Undo restores points; Sync does not remove exclusion list
- Exclusions survive app restart (AsyncStorage)
