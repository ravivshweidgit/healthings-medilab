## Prompt 14 — Food Log: Camera + AI (Gemini Vision) + Macro Tracking

### Goal
Allow the user to log meals by taking a photo or typing a description.
Gemini 2.5 Flash vision AI returns structured macronutrient JSON.
The user can correct the result via chat before saving.
Only the JSON is stored (no photos). The dashboard gains a food macro strip
and meal markers on the glucose/HR timeline.

---

### Vision
This closes the energy loop:

  Net balance = (BMR + Active kcal burned) − Food kcal eaten

Combined with the existing Withings data, the app can now tell the user
whether they are in a fat-loss deficit or muscle-gain surplus on any given day.

---

### Data model

```ts
// app/src/services/FoodLogService.ts

export type FoodItem = {
  name: string;           // English — used for storage and math
  name_local?: string;    // Hebrew or other language — shown in UI
  grams: number;
  kcal: number;
  protein_g: number;
  carb_g: number;
  fat_g: number;
};

export type FoodEntry = {
  id: string;             // uuid (Date.now() + random suffix is fine)
  timestamp: number;      // ms — when the user ate (defaults to now, user can edit)
  items: FoodItem[];
  totalKcal: number;      // precomputed sum
  totalProtein_g: number;
  totalCarb_g: number;
  totalFat_g: number;
  note?: string;          // optional free text ("lunch at work")
  source: 'camera-ai' | 'text-ai' | 'manual';
};
```

**AsyncStorage key pattern**
- One key per day: `food_log_2026-06-01` → `FoodEntry[]` (JSON array)
- Index key: `food_log_days` → `string[]` (list of day keys that have data)

Helper: `dayKeyFromMs(ms: number): string` → `'2026-06-01'` (already in metabolicTrend7d as `localDayKeyFromMs`)

### New files

#### `app/src/services/GeminiService.ts`

Responsibilities:
- Hold the Gemini API key (hardcoded for now, move to .env later)
- `analyzeFood(imageBase64: string | null, userText: string, history: GeminiTurn[]): Promise<FoodItem[]>`
  - If imageBase64 is provided → first turn includes the image (multipart)
  - If imageBase64 is null → text-only turn
  - Appends to history, calls Gemini REST API
  - Parses JSON from response, returns FoodItem[]
  - On parse error: returns items with `name: 'Unknown food'` and zeros (never throws)
- `type GeminiTurn = { role: 'user' | 'model'; text: string; imageBase64?: string }`

**Gemini REST endpoint**
```
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=API_KEY
```

**System instruction (sent as `system_instruction` field, not as a turn)**
```
You are a clinical nutrition AI embedded in a health tracking app.
Your ONLY job is to identify food and return precise macronutrient data.
You NEVER answer general questions.
If the user asks anything unrelated to food, return:
{"items":[],"confidence":"low","description":"Not a food item","suggestion":"Please describe a meal or take a photo of food."}

OUTPUT RULES:
- Return ONLY valid JSON. No markdown. No explanation. No code blocks.
- Never add text before or after the JSON.

RESPONSE FORMAT:
{
  "items": [
    {
      "name": "English dish name",
      "name_local": "name in user language if different",
      "grams": 150,
      "kcal": 248,
      "protein_g": 46.2,
      "carb_g": 0.0,
      "fat_g": 5.1
    }
  ],
  "confidence": "high | medium | low",
  "description": "One sentence: what you identified and how you estimated the portion",
  "suggestion": "Optional: what info would improve accuracy"
}

ESTIMATION RULES:
1. PHOTO MODE: estimate grams from plate context. Standard dinner plate = 26cm diameter.
2. TEXT MODE: "a banana" = medium 120g. Adjust for "big", "small", "half".
3. CORRECTION MODE: user may say "it was bigger" or "add tahini dressing".
   Update the relevant items and return the FULL revised JSON.
   Never drop items that were not mentioned in the correction.
4. Split composite dishes into individual ingredients (e.g. shakshuka → eggs + tomato sauce).
5. Primary source: USDA. For Israeli/Middle-Eastern dishes: Israeli Food Composition Tables.
6. Round kcal to nearest integer. Round macros to 1 decimal place.
7. If you cannot identify the food: return confidence "low" and your best guess.
   Never return an empty items array without attempting an estimate.
```

#### `app/src/components/FoodLogModal.tsx`

Full-screen modal triggered by a floating `+` FAB on the dashboard.

**States / flow:**
1. `idle` — empty screen with two options:
   - `[📷 Take photo]` (expo-image-picker, camera)
   - `[💬 Describe meal]` (text input, no photo)
2. `analyzing` — spinner while Gemini processes
3. `result` — shows the parsed meal card + chat input for corrections
4. `saving` — brief spinner then closes modal

**Meal card (result state):**
```
┌──────────────────────────────────────┐
│  [photo thumbnail 60×60]  Gemini sees:
│  • Grilled chicken   150g   248 kcal │
│  • White rice        180g   234 kcal │
│  • Mixed salad        80g    20 kcal │
│  ────────────────────────────────────│
│  Total  502 kcal · P 48g · C 42g · F 8g │
│  ⚠️ Medium confidence                │
│  💡 "Tell me the brand of hummus…"   │
│                                      │
│  [Chat input: "it was bigger…"]  [↑] │
│  ────────────────────────────────────│
│  [🕐 Edit time: 13:30]               │
│  [✓ Save meal]        [✕ Cancel]     │
└──────────────────────────────────────┘
```

- Each chat correction re-calls `GeminiService.analyzeFood` (text-only, history preserved)
- The meal card rerenders with the updated items
- Photo is NOT stored — only used for the first Gemini call
- Time defaults to current time; user can tap to change (DateTimePicker)
