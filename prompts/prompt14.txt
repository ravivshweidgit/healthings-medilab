## Prompt 14 — Food Log: Camera + AI (Gemini Vision) + Macro Tracking

### Goal
Allow the user to log meals by taking a photo or typing a description.
Gemini 2.5 Flash vision AI returns structured macronutrient JSON.
The user can correct the result via chat before saving, and edit or delete
previously saved meals. The dashboard gains a food macro strip (Section 5)
and orange meal markers on the glucose/HR timeline (Section 1).

---

### Vision
This closes the energy loop:

  Net balance = (BMR + Active kcal burned) − Food kcal eaten

Combined with the existing Withings data, the app can now tell the user
whether they are in a fat-loss deficit or muscle-gain surplus on any given day.

---

### Data model

```ts
// app/src/services/FoodLogService.ts

export type FoodItem = {
  name: string;           // English — used for storage and math
  name_local?: string;    // Hebrew or other language — shown in UI
  grams: number;
  kcal: number;
  protein_g: number;
  carb_g: number;
  fat_g: number;
};

export type FoodEntry = {
  id: string;             // Date.now() + random suffix
  timestamp: number;      // ms — when the user ate (defaults to now, user can edit)
  items: FoodItem[];
  totalKcal: number;      // precomputed sum
  totalProtein_g: number;
  totalCarb_g: number;
  totalFat_g: number;
  note?: string;          // optional free text ("lunch at work")
  source: 'camera-ai' | 'text-ai' | 'manual';
};
```

**AsyncStorage key pattern**
- One key per day: `food_log_2026-06-01` → `FoodEntry[]` (JSON array)
- Index key: `food_log_days` → `string[]` (list of day keys that have data)

### Gemini API — important implementation notes

**Endpoint (v1, not v1beta)**
```
POST https://generativelanguage.googleapis.com/v1/models/gemini-2.5-flash:generateContent?key=API_KEY
```

**Model**: `gemini-2.5-flash` (confirmed available via `GET /v1/models` with this key).
Other models that appeared available at build time: gemini-2.5-pro, gemini-2.0-flash-001,
gemini-2.5-flash-lite, gemini-3.5-flash.

**system_instruction not supported in v1** — embed the system prompt as a synthetic
user/model exchange at the start of every conversation instead:
```json
{ "role": "user",  "parts": [{ "text": "INSTRUCTIONS:\n{SYSTEM_PROMPT}\n\nConfirm you understand." }] },
{ "role": "model", "parts": [{ "text": "{\"items\":[],...}" }] }
```
These synthetic turns must be saved into `updatedHistory` so correction turns
(which skip re-adding system context when `history.length > 0`) still have the
full context available.

**Edit mode context seeding**: when opening an existing meal for editing, inject
the saved items as a synthetic model turn in the conversation history, so the
model knows what's on the plate before the user types a correction.

### Files created

#### `app/src/services/GeminiService.ts`
- `analyzeFood(imageBase64, userText, history)` → `{ result, updatedHistory }`
- `SYSTEM_PROMPT` (exported) — nutrition-only rules, JSON-only output, USDA + Israeli tables
- `MOCK_MODE = false` flag for offline dev testing
- Detailed DEV logging of API errors and response preview

#### `app/src/services/FoodLogService.ts`
- `saveMeal(entry)` — creates or updates (same id = update)
- `getMealsForDay(dayKey)`, `getTodayMeals()`
- `deleteMeal(entryId, timestamp)`
- `getDailyMacros(dayKey)`, `getTodayMacros()`
- `foodLogDayKey(ms)` — shared day key helper
- `seedMockFoodLog()` — pre-populates 3 meals for `__DEV__` testing

#### `app/src/components/FoodLogModal.tsx`

Full-screen modal (pageSheet presentation). Two entry points:
1. **New meal** — idle screen → camera or text → Gemini → result → save
2. **Edit meal** — opens directly in result state with existing items pre-loaded
   and conversation history seeded with the current meal data

**Screens**: `idle → analyzing → result → saving`

**Result screen layout:**
```
[photo thumb]  [confidence badge]
[description text]
┌─ items card ─────────────────────┐
│ Grilled chicken  150g   248 kcal │
│ White rice       180g   234 kcal │
│ ─────────────────────────────── │
│  502 kcal · P 48g · C 42g · F 8g│  ← no "Total" label
└──────────────────────────────────┘
[💡 suggestion box if confidence < high]
[chat input "it was bigger…"]  [→]
[🕐 Meal time: 13:30  Edit]
```

**Action bar (bottom, paddingBottom: 48 to clear Android nav bar):**
- New mode:  `[Cancel]  [✓ Save meal]`
- Edit mode: `[🗑]  [✓ Save meal]  [Cancel]`
  - 🗑 shows a confirmation Alert before deleting

Props: `visible`, `onClose`, `onSaved`, `initialTimestamp?`, `editEntry?: FoodEntry`

#### `app/src/components/FoodMacroStrip.tsx`

Section 5 daily macro summary. Manages its own selected-day state internally.

**Header:**
```
FOOD LOG    ‹  Today  ›    + Add
```
- `‹` / `›` navigate between days (right arrow disabled on today)
- Day label: "Today" / "Yesterday" / "Mon, Jun 1"
- `+ Add` button only shown on today

**Body (when meals exist):**
```
1,890 kcal eaten today
P ████████░░  142g
C ██████████  198g
F █████░░░░░   62g
[Breakfast chip 8:00 · 237 kcal ✎ edit] [Lunch chip…]
```
Each meal chip is tappable → opens FoodLogModal in edit mode.
Macro bars are proportional to the largest macro (no fixed target yet).
