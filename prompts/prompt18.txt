## Prompt 18 — Proactive Mentor Coaching

### Vision
The mentor speaks when there is new data — not on a clock, not when asked.
Every message is grounded in a real event. Action items live inside the chat
so context is always one tap away. The dashboard shows only a lightweight
progress nudge — no duplicate full card.

## PART B — Mentor nudge strip (dashboard inline — lightweight, no full card)

A single tappable row rendered just above the glucose/HR chart on the dashboard.
Shown only when a current (non-dismissed) coach message exists.

```
┌──────────────────────────────────────────────┐
│ 💬 Mentors · 1 of 3 items done   Open →    ✕ │
└──────────────────────────────────────────────┘
```

- **Tap row / "Open →"** → opens ChatScreen (chat opens with the coach message
  already visible as the first bubble, including its action items checklist)
- **✕** → dismisses the strip (sets `dismissedAt`); ChatScreen history still accessible
- Progress count ("1 of 3 done") updates in real time as auto-checks tick items
- No message text and no action item list on the dashboard — those live in ChatScreen

### CoachMessage type (TargetService.ts)

```ts
export type AutoCheckType =
  | 'carbs_under_target'      // done if todayCarb_g <= macroTarget.carb_g
  | 'protein_over_target'     // done if todayProtein_g >= macroTarget.protein_g * 0.9
  | 'calorie_deficit'         // done if todayEaten < todayBurn
  | 'meal_logged'             // done if mealCount > mealCountAtGeneration
  | null;                     // manual tap only

export type CoachActionItem = {
  id: string;
  text: string;
  done: boolean;
  autoCheckType: AutoCheckType;
};

export type CoachMessage = {
  id: string;                      // UUID
  text: string;                    // max 2 sentences from AI
  actionItems: CoachActionItem[];  // 2–4 items
  triggerEvent: 'meal' | 'weigh-in' | 'workout' | 'day-close';
  generatedAt: string;             // ISO
  dismissedAt?: string;            // ISO — set when user taps ✕
  mealCountAtGeneration: number;   // snapshot for 'meal_logged' auto-check
};

const COACH_MESSAGE_KEY = 'coach_message_today';

export async function getCoachMessage(): Promise<CoachMessage | null>
export async function saveCoachMessage(m: CoachMessage): Promise<void>
export async function dismissCoachMessage(): Promise<void>
```

### Auto-check logic

Runs in two places:
1. **On each dashboard load** — to keep the "N of M done" count current in the nudge strip
2. **When ChatScreen opens** — to reflect latest data in the action items checklist

Loop through `actionItems`, apply each `autoCheckType` rule against live `CoachContext`
data, flip `done = true` where conditions are met, and persist with `saveCoachMessage`.

## PART C — Event trigger engine (CoachService.ts — NEW)

```ts
export type CoachTriggerEvent = 'meal' | 'weigh-in' | 'workout' | 'day-close';

/**
 * Call after every relevant event (meal saved, body scan synced, workout synced).
 * Checks frequency rules, calls AI if due.
 * Returns the new CoachMessage or null if skipped (too soon).
 */
export async function triggerCoachReview(
  event: CoachTriggerEvent,
  context: CoachContext,
): Promise<CoachMessage | null>
```

### Frequency gate logic

```ts
const freq = await getMentorFrequency();
const lastMsg = await getCoachMessage();

if (lastMsg && !lastMsg.dismissedAt) {
  const hoursSinceLast = (Date.now() - new Date(lastMsg.generatedAt).getTime()) / 3_600_000;
  if (hoursSinceLast < freq.minGapHours) return null;  // too soon
}

if (event === 'meal' && !freq.afterEachMeal) return null;  // meal events disabled
```

## PART D — GeminiService: generateCoachMessage()

```ts
export type CoachContext = {
  mentors: MentorType[];
  event: CoachTriggerEvent;
  // user profile
  age: number | null;
  gender: string | null;
  heightCm: number | null;
  // body
  weightKg: number | null;
  fatPct: number | null;
  muscleMass_kg: number | null;
  bmr_kcal: number | null;
  startWeight_kg: number | null;
  startMuscle_kg: number | null;
  // today food
  todayEaten: number | null;
  todayBurn: number | null;
  todayProtein_g: number | null;
  todayFat_g: number | null;
  todayCarb_g: number | null;
  mealCount: number;
  // targets
  macroTarget: DailyMacroTarget | null;
  bodyTarget: BodyTarget | null;
  userRules: UserRules | null;
};

export async function generateCoachMessage(ctx: CoachContext): Promise<CoachMessage>
```

### Prompt template

```
{mentorSystemPrompt}

EVENT: {event} (meal logged / new weigh-in / workout synced / day close)

USER DATA:
Weight: {w} kg (start: {startW} kg, target: {targetW} kg)
Muscle: {m} kg (start: {startM} kg, target: {targetM} kg)
Today eaten: {eaten} kcal / {targetKcal} | P: {p}g/{tp}g | C: {c}g/{tc}g | F: {f}g/{tf}g
Today burned: {burn} kcal | Balance: {balance} kcal
Meals logged today: {mealCount}
Dietary rules: {rulesContext}

Respond with JSON only:
{
  "text": "2 sentences max. Specific numbers. No generic advice.",
  "actionItems": [
    {"text": "Stay under 20g carbs today", "autoCheckType": "carbs_under_target"},
    {"text": "Add 20g protein at dinner",  "autoCheckType": null},
    {"text": "Log next meal",              "autoCheckType": "meal_logged"}
  ]
}

Rules:
- text: max 2 sentences, cite specific numbers from the data, no generic advice
- actionItems: 2–4 items, max 8 words each, concrete and actionable today
- autoCheckType: use the matching type if applicable, otherwise null
- If event is meal: focus on remaining macros for the day
- If event is weigh-in: focus on trend vs target, muscle vs start
- If event is workout: focus on calorie budget impact
- Do NOT repeat data the user already sees on the dashboard
```

Config: `temperature: 0.3`, `maxOutputTokens: 8192`

## PART E — Manual "Review now" (user-initiated, bypasses frequency gate)

The user can always request an immediate mentor review, ignoring the minimum gap.

### Entry points

1. **Nudge strip** — when the strip is visible, show a subtle "↻ Refresh" link
   on the right side. Tapping regenerates with current data.

2. **Floating pill** — two behaviours:
   - **Tap** → open ChatScreen (free dialogue)
   - **Long-press** → trigger immediate mentor review → generates new message,
     nudge strip appears / refreshes, ChatScreen auto-opens to show it

3. **No strip showing** (dismissed or first launch) → pill tap shows a small menu:
   ```
   ┌──────────────────────────┐
   │  💬  Chat with mentors   │
   │  ↻   Review my status    │
   └──────────────────────────┘
   ```

### CoachService addition

```ts
/**
 * Same as triggerCoachReview() but skips the frequency gate.
 * Used for manual user-initiated reviews.
 */
export async function forceCoachReview(
  context: CoachContext,
): Promise<CoachMessage>
```

### UX note
- After "Review now" completes, the nudge strip appears/refreshes on the dashboard
- The `generatedAt` timestamp is updated — so the next automatic check counts
  from this manual review
- No limit on how often the user can manually review

## PART F — Free chat (ChatScreen.tsx — NEW)

Opened from the nudge strip "Open →", or from the floating pill.

Full-screen modal. Inherits all context from CoachContext.

```
┌─────────────────────────────────────────────┐
│  ←  💬 My Mentors  🥗💪                      │
├─────────────────────────────────────────────┤
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │ You're 0.2 kg below muscle target.  │    │  ← AI bubble (coach msg)
│  │ Protein on track (127/148g).        │    │
│  │                                     │    │
│  │ ☐  Add 20g protein at dinner        │    │  ← action items checklist
│  │ ☑  Stay under 20g carbs             │    │     inside the bubble
│  │ ☐  Log next meal                    │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  [user messages right, AI left]             │
│                                             │
├─────────────────────────────────────────────┤
│  [Review my status] [Review last meal] [+]  │  ← quick-question chips
│  ┌──────────────────────────┐  [Send]        │
│  │ Ask your mentors…        │                │
│  └──────────────────────────┘                │
└─────────────────────────────────────────────┘
```

### Action items inside the coach bubble
- Rendered as a checklist at the bottom of the first AI bubble
- Checkboxes are tappable — manual tap toggles `done`; auto-checks tick automatically
  when ChatScreen opens (same logic as dashboard, runs against live data)
- Ticking / unticking persists via `saveCoachMessage`
- The nudge strip "N of M done" count on the dashboard reflects these changes

### Chat history model

**One chat, per-day scope.** History resets at midnight (same boundary as Withings).
No per-mentor threads — all mentors respond as a unified panel voice.

#### Storage (TargetService.ts additions)

```ts
export type ChatMessage = {
  role: 'user' | 'assistant';
  text: string;
  sentAt: string;  // ISO
};

const CHAT_HISTORY_KEY = 'chat_history_';  // + 'YYYY-MM-DD'
const CHAT_YESTERDAY_SUMMARY_KEY = 'chat_yesterday_summary';  // plain string

export async function getChatHistory(date: string): Promise<ChatMessage[]>
// date = 'YYYY-MM-DD', returns [] if none

export async function appendChatMessage(date: string, msg: ChatMessage): Promise<void>
// Appends to today's array; trims to last 30 messages if needed

export async function getYesterdaySummary(): Promise<string | null>
export async function saveYesterdaySummary(summary: string): Promise<void>
```

#### Yesterday's context (one-sentence handoff)

On the **first chat open of a new day**, if yesterday's history exists and no
summary has been saved yet:
1. Call `summariseChatDay(history)` in GeminiService — a lightweight call:
   `"Summarise yesterday's health chat in one sentence (max 20 words)."`
2. Store the result in `CHAT_YESTERDAY_SUMMARY_KEY`.
3. Prepend it silently to the system prompt for all of today's chat calls:
   `"Yesterday: {summary}"`

This provides continuity ("you hit your carb goal yesterday") without growing
the token budget as the day progresses.

#### Sent to AI each turn
- System prompt (mentor personas + user rules + yesterday summary if available)
- CoachContext data block (same as `generateCoachMessage`)
- Last **20** messages from today's history

GeminiService: `chatWithMentors(message, history, context, yesterdaySummary)`.
Temperature 0.4.

## PART F2 — Quick Questions (user-editable chat shortcuts)

Up to 3 quick-question chips shown above the input bar in ChatScreen.
Tapping a chip sends that question immediately (no extra confirm step).
Long-pressing a chip opens inline editing to rename it.

### Defaults (shipped with the app, used if nothing stored)
```
"Review my status"
"Review my last meal"
"How am I doing today?"
```

### Storage (TargetService.ts addition)
```ts
export type QuickQuestion = {
  id: string;    // stable UUID assigned on first save
  label: string; // display text, also the message sent
};

const QUICK_QUESTIONS_KEY = 'chat_quick_questions';

export async function getQuickQuestions(): Promise<QuickQuestion[]>
// Returns saved list, or the 3 defaults if nothing stored yet.

export async function saveQuickQuestions(qs: QuickQuestion[]): Promise<void>
```

### UI behaviour
- Chips shown in a single horizontal scrollable row above the text input
- **Tap** → text is sent immediately as a user message
- **Long-press** → chip label becomes an editable `TextInput` inline;
  confirm with keyboard "Done" key → auto-saved
- A **＋** chip at the far right adds a new question (max 3 total)
- During inline edit, a **✕** appears next to the field to delete that chip
- No separate settings screen — all editing is inline in ChatScreen

## PART G — Floating pill + dashboard wiring (DashboardScreen.tsx)

### Floating pill
```jsx
<Pressable
  style={styles.chatPill}
  onPress={() => setChatVisible(true)}
  onLongPress={() => handleForceReview()}
>
  <Text style={styles.chatPillText}>{mentorEmojis}  Ask mentors</Text>
</Pressable>
```
Style: `position: absolute`, bottom 16, `alignSelf: 'center'`, dark pill,
white text. Always visible. `zIndex: 100`.

### Trigger points
Call `triggerCoachReview()` after:
1. `handleFoodSaved()` — meal saved → event: `'meal'`
2. After Withings body scan syncs → event: `'weigh-in'`
3. After Health Connect workout syncs → event: `'workout'`

### Day-close trigger (midnight boundary — aligns with Withings)

On every dashboard mount, check:
```ts
const lastDayClose = await AsyncStorage.getItem('last_day_close_date'); // 'YYYY-MM-DD'
const today = new Date().toISOString().split('T')[0];
if (lastDayClose !== today) {
  await AsyncStorage.setItem('last_day_close_date', today);
  triggerCoachReview('day-close', context);
}
```
Fires once on the first open of each new day — same midnight boundary Withings uses.

### Dashboard scroll padding
Add `paddingBottom: 100` to `contentContainerStyle` of main ScrollView so
content is not hidden behind the floating pill.
