## Prompt 18 — Proactive Mentor Coaching

### Vision
The mentor speaks when there is new data — not on a clock, not when asked.
Every message is grounded in a real event. Action items live inside the chat
so context is always one tap away. The dashboard shows only a lightweight
progress nudge — no duplicate full card.

## PART B — Mentor nudge strip (dashboard inline — lightweight, no full card)

A single tappable row rendered just above the glucose/HR chart on the dashboard.
Shown whenever a current coach message exists.

```
┌──────────────────────────────────────────────┐
│ 💬 Mentors · 1 of 3 items done   Open →    │
└──────────────────────────────────────────────┘
```

- **Tap row / "Open →"** → opens ChatScreen (coach panel pinned at top; chat scrolls below)
- **No ✕ dismiss** — dismissing the strip accidentally hid action items in chat (removed)
- **No ↻ on dashboard** — refresh only in ChatScreen where the user sees the result (removed)
- Progress count ("1 of 3 done") updates in real time as auto-checks tick items
- No message text and no action item list on the dashboard — those live in ChatScreen

### CoachMessage type (TargetService.ts)

```ts
export type AutoCheckType =
  | 'carbs_under_target'      // done if todayCarb_g <= macroTarget.carb_g
  | 'protein_over_target'     // done if todayProtein_g >= macroTarget.protein_g * 0.9
  | 'calorie_deficit'         // done if todayEaten < todayBurn
  | 'meal_logged'             // done if mealCount > mealCountAtGeneration
  | null;                     // manual tap only

export type CoachActionItem = {
  id: string;
  text: string;
  done: boolean;
  autoCheckType: AutoCheckType;
};

export type CoachMessage = {
  id: string;                      // UUID
  text: string;                    // combined fallback / single-mentor text
  mentorLines?: Partial<Record<MentorType, string>>;  // one sentence per active mentor when 2+
  actionItems: CoachActionItem[];  // 2–4 items
  triggerEvent: 'meal' | 'weigh-in' | 'workout' | 'day-close';
  generatedAt: string;             // ISO
  mealCountAtGeneration: number;   // snapshot for 'meal_logged' auto-check
  generatedLangCode?: string;    // BCP-47 code when message was created (language sync)
};

// Legacy `dismissedAt` in AsyncStorage is migrated away on load (recover action items).

const COACH_MESSAGE_KEY = 'coach_message_today';

export async function getCoachMessage(): Promise<CoachMessage | null>
export async function saveCoachMessage(m: CoachMessage): Promise<void>
export async function dismissCoachMessage(): Promise<void>
export async function clearCoachMessage(): Promise<void>
export async function clearChatHistory(date: string): Promise<void>
```

### Auto-check logic

Runs in two places:
1. **On each dashboard load** — to keep the "N of M done" count current in the nudge strip
2. **When ChatScreen opens** — to reflect latest data in the action items checklist

Loop through `actionItems`, apply each `autoCheckType` rule against live `CoachContext`
data, flip `done = true` where conditions are met, and persist with `saveCoachMessage`.

## PART C — Event trigger engine (CoachService.ts — NEW)

```ts
export type CoachTriggerEvent = 'meal' | 'weigh-in' | 'workout' | 'day-close';

/**
 * Call after every relevant event (meal saved, body scan synced, workout synced).
 * Checks frequency rules, calls AI if due.
 * Returns the new CoachMessage or null if skipped (too soon).
 */
export async function triggerCoachReview(
  event: CoachTriggerEvent,
  context: CoachContext,
): Promise<CoachMessage | null>
```

### Frequency gate logic

```ts
const freq = await getMentorFrequency();
const lastMsg = await getCoachMessage();

if (lastMsg && !lastMsg.dismissedAt) {
  const hoursSinceLast = (Date.now() - new Date(lastMsg.generatedAt).getTime()) / 3_600_000;
  if (hoursSinceLast < freq.minGapHours) return null;  // too soon
}

if (event === 'meal' && !freq.afterEachMeal) return null;  // meal events disabled
```

Also export:

```ts
export async function checkCoachReviewGate(): Promise<
  { allowed: true } | { allowed: false; waitHours: number; minGapHours: number }
>;

/** Manual refresh — respects min-gap only (not meal toggle). */
export async function refreshCoachReview(
  context: CoachContext,
  event?: CoachTriggerEvent,
): Promise<
  | { ok: true; message: CoachMessage }
  | { ok: false; reason: 'too_soon'; waitHours: number; minGapHours: number }
>;

/** Bypasses frequency gate — used internally for language-mismatch regen only. */
export async function forceCoachReview(context: CoachContext): Promise<CoachMessage>
```

Event triggers wired in `DashboardScreen.tsx`:
1. `handleFoodSaved()` → `'meal'`
2. New Withings `measuredAt` on body scan sync → `'weigh-in'`
3. New workout session today → `'workout'`
4. First open of each calendar day → `'day-close'`

### Prompt template

```
{mentorSystemPrompt}

EVENT: {event} (meal logged / new weigh-in / workout synced / day close)

USER DATA:
Weight: {w} kg (start: {startW} kg, target: {targetW} kg)
Muscle: {m} kg (start: {startM} kg, target: {targetM} kg)
Today eaten: {eaten} kcal / {targetKcal} | P: {p}g/{tp}g | C: {c}g/{tc}g | F: {f}g/{tf}g
Today burned: {burn} kcal | Balance: {balance} kcal
Meals logged today: {mealCount}
Dietary rules: {rulesContext}

Respond with JSON only:
{
  "mentorLines": {
    "nutritionist": "one sentence with numbers",
    "coach": "one sentence with numbers"
  },
  "actionItems": [
    {"text": "Stay under 20g carbs today", "autoCheckType": "carbs_under_target"},
    {"text": "Add 20g protein at dinner",  "autoCheckType": null},
    {"text": "Log next meal",              "autoCheckType": "meal_logged"}
  ]
}

Rules:
- When 2+ active mentors: use `mentorLines` — one key per active mentor, one sentence each with numbers; do NOT blend into one paragraph
- Single mentor: `mentorLines` with one key OR legacy `text` field
- actionItems: 2–4 items, max 8 words each, concrete and actionable today
- autoCheckType: use the matching type if applicable, otherwise null
- If event is meal: focus on remaining macros for the day
- If event is weigh-in: focus on trend vs target, muscle vs start
- If event is workout: focus on calorie budget impact
- Do NOT repeat data the user already sees on the dashboard
```

Config: `temperature: 0.3`, `maxOutputTokens: 8192`

## PART E — Manual refresh (user-initiated, respects min-gap)

Regenerating coach text + action items uses **`refreshCoachReview()`** — same
min-gap setting as automatic events (MentorStrip slider). No bypass from the UI.

### Entry points

1. **ChatScreen coach panel footer ↻ Refresh / ↻ רענן** — gated refresh; alert if too soon
2. **Quick-question chips** — "Review my status" etc. fill the input; user taps
   **Send** for a free-chat answer (does not regenerate the action-item list)

### Not used (removed during implementation)

- **Nudge strip ↻** — removed; user could not see refresh result until opening chat
- **Nudge strip ✕** — removed; incorrectly hid action items from chat permanently
- **Floating "Ask mentors" pill** — removed; duplicated nudge strip entry
- **Force review on every tap** — `forceCoachReview()` retained only for
  language-mismatch auto-regeneration (`generatedLangCode` ≠ user language)

### UX note
- After refresh completes, coach panel **stays expanded** (do not re-collapse on new `coachMsg.id`)
- Nudge strip progress count updates via `onCoachMessageUpdated`
- If min-gap not met, show alert: e.g. "Try again in about 3h" / "עוד מוקדם לרענון"

## PART F — Free chat (ChatScreen.tsx — NEW)

Opened from the nudge strip only (no floating pill).

Full-screen modal inside `SafeAreaProvider`. Inherits `CoachContext` from dashboard
(includes `mentorGender`, `lang`, active `mentors`).

```
┌─────────────────────────────────────────────┐
│  ←  💬 המנטוריות שלי                         │
├─────────────────────────────────────────────┤
│ ▶ משימות · 1/4   [collapsible coach panel]  │  ← pinned top; scroll inside when open
│   (🥗 / 💪 / 🩺 separate voice cards)         │
├─────────────────────────────────────────────┤
│  [messages for ACTIVE TAB only — scrolls]   │
│                                             │
├─────────────────────────────────────────────┤
│  🥗 התזונאית │ 💪 המאמנת │ 🩺 הרופאה        │  ← pinned mentor tabs
│  ┌──────────────────────────┐               │
│  │ Ask…                     │               │
│  └──────────────────────────┘               │
│  ↑ ↓  נקה  ↗  [שלח]                         │  ← single-row toolbar
│  [chip] [chip] [chip]              [FAQ]    │
└─────────────────────────────────────────────┘
```

### Collapsible coach panel
- **Pinned above** message list — not in FlatList scroll
- **Starts collapsed** on open (even after refresh); user expands to read tasks
- **Expanded body** — when 2+ mentors, **separate cards** per voice from `mentorLines`
  (🥗 green / 💪 blue / 🩺 purple tints); fallback splits blended text via `mentorChatText.ts`
- **Internal ScrollView** `maxHeight: 220` when expanded — panel never fills the screen
- **↻ Refresh** in panel header — gated `refreshCoachReview()`; does not auto-expand
- Checkboxes tappable; auto-checks on open; persists via `saveCoachMessage`
- **Clear chat** moved to bottom toolbar (see below) — not in coach footer

### Per-mentor chat tabs (shipped)
- One tab per **active** mentor (`MENTOR_CHAT_TAB_ORDER`: nutritionist → coach → doctor)
- Tab label = possessive + emoji (e.g. `🥗 התזונאית שלי`) — gender from `mentorGender`
- Each tab has **its own history** and **its own API call** — no blended multi-mentor reply
- Switching tabs loads that mentor's messages; bubble colours match mentor accent
- `chatWithMentor(mentor, message, history, ctx, yesterdaySummary)` in GeminiService
- `chatWithMentors()` retained as deprecated wrapper (uses first mentor only)

### Bottom chrome (pinned — never scrolls off screen)
- Mentor tabs + text input + action toolbar live in `bottomChrome` (`flexShrink: 0`)
- Parent flex chain uses `minHeight: 0` so FlatList does not push chrome off-screen
- **Toolbar (single row, no wrap):**
  - `↑` / `↓` — scroll message list to top / bottom
  - `נקה` — clears **active tab only** (`clearChatHistory(date, mentors, activeMentor)`)
  - `↗` — HTML export (icon only; `accessibilityLabel` = export label)
  - `שלח` / Send — send message to active mentor
- Export enabled when coach message exists OR any mentor has chat history

### Safe area
- `react-native-safe-area-context` on app root + inside chat `Modal`
- Bottom input padded above Samsung system nav bar

### Chat history model

**Per-mentor threads, per-day scope.** History resets at midnight (same boundary as Withings).

#### Storage (TargetService.ts)

```ts
export type ChatMessage = {
  role: 'user' | 'assistant';
  text: string;
  sentAt: string;  // ISO
};

const CHAT_HISTORY_KEY = 'chat_history_';  // + 'YYYY-MM-DD' + '_' + mentor
// Legacy unified key chat_history_YYYY-MM-DD still read by hasAnyChatHistory only

export async function getChatHistory(date: string, mentor: MentorType): Promise<ChatMessage[]>
export async function getAllChatHistories(date: string, mentors: MentorType[]): Promise<Partial<Record<MentorType, ChatMessage[]>>>
export async function appendChatMessage(date: string, mentor: MentorType, msg: ChatMessage): Promise<void>
export async function clearChatHistory(date: string, mentors: MentorType[], mentor?: MentorType): Promise<void>
export async function getYesterdaySummary(): Promise<string | null>
export async function saveYesterdaySummary(summary: string): Promise<void>
```

#### Yesterday's context (one-sentence handoff)

On the **first chat open of a new day**, if yesterday's history exists and no
summary has been saved yet:
1. Call `summariseChatDay(history)` in GeminiService — a lightweight call:
   `"Summarise yesterday's health chat in one sentence (max 20 words)."`
2. Store the result in `CHAT_YESTERDAY_SUMMARY_KEY`.
3. Prepend it silently to the system prompt for all of today's chat calls:
   `"Yesterday: {summary}"`

This provides continuity ("you hit your carb goal yesterday") without growing
the token budget as the day progresses.

#### Sent to AI each turn (per active tab)
- System prompt (single mentor persona + user rules + yesterday summary if available)
- CoachContext data block including **=== MEAL LOG ===** full item detail for today
- Last **20** messages from **that mentor's** history for today
- Meal-review queries also repeat `todayMealsDetail` in the user turn

GeminiService: `chatWithMentor(mentor, ...)`. Coach/action-item text follows `UserLanguage`.
Temperature 0.4.

## PART G — Dashboard wiring (DashboardScreen.tsx)

### Chat entry
- **Nudge strip only** — no floating pill (removed: overlapped system nav bar and
  duplicated nudge). Strip is always tappable while a coach message exists.

### Trigger points
See PART C — all four events wired with `triggerCoachReview()` + frequency gate.

### Day-close trigger (midnight boundary — aligns with Withings)

On every dashboard mount, check:
```ts
const lastDayClose = await AsyncStorage.getItem('last_day_close_date'); // 'YYYY-MM-DD'
const today = new Date().toISOString().split('T')[0];
if (lastDayClose !== today) {
  await AsyncStorage.setItem('last_day_close_date', today);
  triggerCoachReview('day-close', context);
}
```

### Scroll padding
`paddingBottom` on main ScrollView includes safe-area inset (no pill offset).

### Language
User language picker in My Profile; threaded into all Gemini calls; coach message
cleared/regenerated when `generatedLangCode` mismatches selected language.
