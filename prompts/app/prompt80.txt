## Prompt 80 — Hybrid activity: phone steps + Withings bike (raw store, calc-only factor)

**Status: backlog (drafted 2026-07-20)** — not shipped  
**Builds on:** `done/prompt76` (phone health when watch off), `done/prompt70` (Food Log burn), `done/prompt73` (watch activity on manual weight), persistence parity rules

### Problem

Withings **workout kcal** (and Health Mate itself) can disagree ~**27–46%** across phones/accounts for the same rides. Investigation (cloud backups `raviv.shweid@gmail.com` vs `raviv.shweid+withings-ios@gmail.com`, Jul 18–19 2026):

| Finding | Detail |
|---------|--------|
| Gap location | `getworkouts` kcal — not Food Log math, not cloud backup |
| Health Mate | Same ~+27% iOS vs Android on activity kcal (screenshots) |
| Passive intraday | Close between accounts; workouts drive the delta |
| Walk sessions | Watch walk workouts also inflate; phone steps felt more trustworthy |
| Dual-link same Withings user | Risky (OAuth token kick); not required to conclude |

Today **Watch = Yes** uses Withings for **all** activity (prompt76). That inherits Withings estimate noise for walking and bikes.

### Product rule (target)

| Signal | Source when Withings watch is **on** |
|--------|--------------------------------------|
| **Steps / walking energy** | **Phone** (HC / Apple Health / Samsung steps path) — always |
| **Walk workouts from watch** | **Ignore** for Food Log / coach burn (do not add) |
| **Bike + other non-walk workouts** | **Withings** `getworkouts` (keep raw kcal in store) |
| **Withings intraday passive cal** | **Do not** use for burn when phone steps are active (no double-count) |
| **BMR / body / HR** | Unchanged (existing Withings / scale / phone HR rules) |
| **Calibration** | Optional multiplier on **non-walk workout kcal only** (default `1.0`) — **calculate at burn time only**; never rewrite `metricsStore` |

When Withings watch is **off**, keep prompt76 (phone health only).

### Burn formula (Food Log / coach)

```text
activity ≈ stepsToKcal(phoneSteps)           // existing 0.55 × kg × km path
         + Σ (workout.kcal × calibration)    // Withings, category ∉ walk
totalBurn ≈ BMR + activity
```

**Double-count guard:** on bike days, phone still logs some steps — acceptable small overlap; do **not** also add Withings passive or walk sessions. Prefer documenting over complex step-window subtraction in v1.

### Calibration (not Platform.OS)

- Store preference e.g. `activityWorkoutCalibration` (float, default `1`) in app settings / backup JSON — **not** an `ios`/`android` clinic column.
- Do **not** hardcode `0.7` or `Platform.OS === 'ios'`.
- Clinic / visit report: show **raw** workouts by default; if burn is shown, use same formula + factor from snapshot if present.

### Persistence parity

- Canonical store stays `healthings:metricsStore` — raw Withings workouts + phone step totals as today.
- Adapters merge in; burn is a **derived** view in Dashboard / Food Log.
- No platform-prefixed keys.

### Investigation log (2026-07-20) — what we did & how we compared

#### Goal

Explain why iOS appeared ~30% higher on activity kcal than Android for the same person/days. Determine whether the bug was Healthings (Food Log formula, backup, platform parse) or Withings (API / Health Mate).

#### Data sources (VPS Postgres)

| Source | Email | Role |
|--------|-------|------|
| `user_cloud_backups` current (+ prev) | `raviv.shweid@gmail.com` | Android production (fingerprint `glucose: health-connect`) |
| `user_cloud_backups` current | `raviv.shweid+withings-ios@gmail.com` | iOS TestFlight test account (`glucose: healthkit`) |
| `sync_blobs` (clinic) | main account | Stale for Jul 18–19 (last v82 = 2026-07-17); used only for platform fingerprints |

**Important:** one cloud slot per Healthings user (`current` + one `prev`). Main-account current/prev were both Android when re-checked after an Android backup (22:34Z). True iOS-vs-Android A/B on **one** email was not completed (dual Withings link risks OAuth kick). Compare used **two Healthings users** linked to different Withings sessions/profiles.

Platform guess from `source_config.glucose`: `health-connect` → Android, `healthkit` → iOS.

#### Method

1. Inflate gzip cloud payloads → parse `asyncStorage['healthings:metricsStore']`.
2. Day keys in **Asia/Jerusalem** (`en-CA` calendar dates).
3. Replicate Dashboard `withingsActivityForDay` (Food Log path):
   - Sum Withings workout `kcal` for the day (skip `health-connect` workouts).
   - Sum intraday `calories[]` points **outside** 30‑minute buckets overlapping any workout window.
   - `activity = round(passiveKept + workoutKcal)`; `totalBurn = BMR + activity` when BMR present.
4. Fuzzy-match workouts across backups: same `category`, `|startMs| ≤ 5 min`.
5. Cross-check Health Mate screenshots (user-supplied) for the same ballpark day.

#### What we ruled out

- Cloud backup corruption / Food Log `max` vs add bug as root cause of the 30% gap  
- Need for clinic `ios`/`android` column for a future calibration factor  
- Same-account dual-phone Withings re-link as a required proof (Health Mate already disagreed)

#### Conclusion

Withings (Health Mate + `getworkouts`) returns higher activity/workout estimates on the iOS test link than on the Android production link. Healthings correctly mirrors stored/API numbers. Product response: **hybrid activity** (this prompt) — phone steps for walking, Withings for non-walk workouts, raw store, optional calc-only calibration.
