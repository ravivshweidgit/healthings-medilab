# prompt117 — Keep original lab PDF beside parsed rows (clinic compare)

**Status:** done (2026-08-23) — Android `bi` + clinic site deployed; owner accepted  
**Builds on:** prompt30 (lab JSON), prompt112 (HMO parse), prompt116 (sidecar-on-disk, not base64 in JSON)

## Problem

Gemini can put a neighbor’s number on LDL (Clalit: value **above** the name; NON-HDL
sits next to LDL). JSON is what charts and mentors trust. The clinician (and the
patient) need the **printout next to the rows** to catch that. Putting PDF bytes
inside `lab_report_*` JSON would bloat every backup and the 15 MB clinic gzip cap
(same lesson as meal thumbs).

## What shipped

| Piece | Change |
|-------|--------|
| Parsed rows | `lab_report_{id}` JSON (unchanged) |
| Original PDF | `documentDirectory/healthings-lab-pdfs/{panelId}.pdf` |
| Pointer | `LabPanel.pdfFileId` (= panel `id`) — no `Platform.OS` in path or key |
| Phone open | **Open original PDF** uses Android `content://` VIEW (Chrome / Drive / PDF app); share sheet is fallback |
| Clalit parse | Layout pack: value above name; draw date = `תאריך הבדיקה`; LDL ≠ NON-HDL |
| Swap repair | Friedewald LDL/NON-HDL repair on parse, save, and load |
| Share / backup | inject `healthings:labPdfs` at export; **not** left in live AsyncStorage after restore |
| Clinic Labs | **Original PDF** → lightbox: PDF + that draw’s table |
| Mentors | lab JSON only — never PDF bytes |

Keep PDFs for the life of the report. Delete the file when the report is deleted.
Old reports have no file until that PDF is imported again on this build.
