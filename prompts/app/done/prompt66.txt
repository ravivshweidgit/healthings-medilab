## Prompt 66 — Macro target stability (history + dampened auto-apply)

**Status: done (code 2026-07-13; closed 2026-07-25)** — shipped in `e6356c1`, context follow-up in `ccaa228`.
**Builds on:** `done/prompt35.txt` · `done/prompt42.txt` · `done/prompt44.txt`  
**Problem:** AI macro targets jump day-to-day (e.g. carbs 75 → 65) because each revise fully regenerates without holding prior targets; food-log bars always use the *current* global target for past days.

### What shipped

| Piece | Behavior |
|-------|----------|
| Per-day snapshot | `macro_target_by_day_v1` — on `saveMacroTarget` and first open of day (`ensureMacroTargetDaySnapshot`) |
| Food log bars | `getMacroTargetForDay(dayKey)` so yesterday’s meals are judged vs yesterday’s targets |
| Auto-apply dampener | EMA 70/30 toward AI + daily caps (~±5% carbs clamped 3–8 g, ±5 g P/F, ±120 kcal) via `dampenMacroSuggestion` |
| Gemini context | Inject active + last 7 day targets; instruct hold-steady / small titrations (no longer “do not copy prior”) |
| Explicit Accept | `/macros` / dashboard Accept still saves full proposal (no dampener) |
| Directive override (follow-up `ccaa228`) | When a nutritionist directive carries kcal, the prior-targets block flips to “large jumps from active targets are required” — directive wins over stability |
