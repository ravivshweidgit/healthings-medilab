## Prompt 49 — Link to clinic + share data with sponsor

**Status: backlog (49a partial — `ClinicLinkStrip.tsx` + `ShareApiService.ts` in local WIP; 49b not started)**  
**Builds on:** `done/prompt-be-02b-app-login.md` · `prompts/backend/prompt-be-03-account-shares.md` · `prompt-be-04` · `prompt-be-06`.

---

### Product decisions (locked 2026-07 — align with `prompt-be-04`)

| Decision | Rule |
|----------|------|
| **Payload** | Encrypted **image of phone persistence** — same JSON subset as `LocalBackupService` / App Backup. Not live phone access. |
| **Default window** | **Last 90 days** (`lookbackMode: '90d'`). |
| **Extended window** | Patient may choose **Full history on phone** (`lookbackMode: 'full'`) — e.g. clinic wants 5 years. Patient controls what leaves the device. |
| **Clinic visibility** | **Once shared, clinic can view all data in that snapshot** — meals, CGM, labs, Withings, rules, targets (read-only). All-or-nothing per upload; no per-field ACL in MVP. |
| **Updates** | New phone data → patient taps **Share** again (new blob version). Clinic uses **latest** unless viewing history. |
| **Compression** | JSON → **gzip** → encrypt → upload. ~2.5 MB raw (2 mo) → ~240 KB gzip; 90d steady ~280 KB; 5y full ~1.2 MB gzip. |
| **Not on link approve** | Approving a clinic link does **not** auto-upload — patient must tap **Share data** explicitly. |

```ts
buildClinicExport({ lookbackMode: '90d' | 'full' })  // default '90d'
```

### Problem

Patients can sign in, but the app still needs:

- ~~Link to a clinic/nutritionist~~ (49a WIP — request/approve/revoke in `ClinicLinkStrip`)
- **Share local phone data** with an approved clinic (encrypted upload — **49b**)
- Show **last shared** timestamp + lookback label (90d vs full)
- See when **AI is sponsored** by the clinic (49a WIP — wallet badge)

Clinics use the **web portal** (be-05); patients use this app prompt.

### What ships

#### 49a — Account / clinic link strip

**Surface:** `ClinicLinkStrip.tsx` on dashboard (partial WIP).

| State | UI |
|-------|-----|
| No link | Enter clinic email → `POST /v1/shares/request` |
| Pending (they invited you) | “&lt;clinic&gt; invited you” → Approve / Reject |
| Pending (you requested) | “Waiting for &lt;clinic&gt; to approve” |
| Approved | “Shares data with &lt;clinic&gt;” + **Share data** + Revoke + last-shared line |
| Approved + sponsor | “AI sponsored by &lt;clinic&gt;” (from `/v1/wallet`) |

On login: `GET /v1/shares/pending-for-me` — show badge if action needed.

**Last shared line (when blob exists):** `Shared · 28 Jun 2026 · 90 days` or `Shared · … · full history`

#### 49b — Share with clinic (encrypted upload)

**Service:** `ShareExportService.ts` (see `prompt-be-04`)

1. **Confirm dialog** — patient picks window:
   - **90 days (recommended)** — default; ~280 KB upload
   - **Full history on phone** — when clinic needs long range (e.g. 5 years); larger upload (~1 MB+ gzip)
   - List what is included: meals, CGM, labs, Withings (weight/HR/workouts), rules, targets
   - Explicit: “Clinic will see **all** data in this snapshot”
2. `buildClinicExport({ lookbackMode })` — reuse `LocalBackupService` key list + time filter; exclude tokens/secrets (`EXCLUDED_ASYNC_KEYS`, no `withingsTokens`)
3. JSON → gzip → encrypt (AES-256-GCM per be-04) → `POST /v1/sync/upload` with `summary.lookbackMode`
4. Success: “Shared with &lt;clinic&gt; · &lt;timestamp&gt; · 90 days” (or “full history”)
5. Error: retry; offline queue (optional v2)

**Not automatic on link approve** — patient explicitly taps **Share**. Optional “Share automatically weekly” → v2.

#### 49c — Revoke

- Revoke link → `POST /v1/shares/:id/revoke`
- Prompt: “Clinic will lose access to future data. Delete copies on server?” → optional delete blobs (be-04)

#### 49d — Clinic plan updates (medical rules)

When `GET /v1/plans/pending` returns rows:

1. Banner on dashboard / Medical rules strip: **“&lt;Clinic&gt; sent a new plan”**
2. Tap → download PDF → **`MedicalRulesReviewScreen`** (shared with prompt46 import)
3. **Apply** → save `medical_rules` locally → `POST /v1/plans/:id/applied`
4. **Dismiss** (optional) — stays pending until apply or superseded

On app open + after login: poll pending plans if linked to clinic.

#### 49e — Solo path unchanged

- No clinic required; app fully usable
- Patient pays own AI when be-06 live (wallet UI minimal: balance in Account)

### Phone-tested checklist

- [ ] Request clinic by email → clinic sees pending on web (be-05)
- [ ] Approve clinic invite → approved state + sponsor badge
- [ ] Share data (default 90d) → clinic portal shows last sync + **all** chart sections

- [ ] Re-share after new meals → clinic latest blob updates
