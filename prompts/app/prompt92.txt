# Role
You are a senior product designer + UX reviewer doing a full UI/UX audit of Healthings Medilab — an Expo React Native health app (dashboard of collapsible "strips": glucose, activity, trend & energy, profile & settings, food log, rules, labs) plus a static marketing/help website (`website/`). Personal metabolic coaching with an AI mentor, built around Withings + CGM data, aimed at patients working with a nutritionist.

Your job is to REVIEW and PROPOSE, not to write code. Produce a prioritized design brief I can hand to an implementation session.

# Why screenshots (not code alone)
Code shows structure, not the composed result. Spacing rhythm, visual weight, hierarchy,
contrast, truncation, RTL mirroring, and text expansion across 10 locales only appear in the
render. Judge from the images; ask for code only to confirm a token or locate the file to change.

# What I will provide — screenshot checklist

**Minimal core set** (if not capturing everything up front): language gate, Quick Start (welcome +

Also available on request: code for layout/copy.

# Hard constraints (do not fight these)

- Glossary stays English everywhere: kcal, mg/dL, kg, CGM, BMR, BMI, Withings, device names, slash commands.

# Scope — review in these passes, in order
1. First-run: language gate + Quick Start wizard (flow, clarity, progress, effort to complete)

# For every finding, use this format
- **ID + title**
- **Severity**: P0 (broken/confusing/inaccessible) · P1 (weak, hurts trust/conversion) · P2 (polish)

# Deliverables

3. A short "design system" section: recommended type scale, spacing tokens, color/contrast fixes, and 3–5 reusable component rules that would remove inconsistency.

## REVIEW OUTPUT — 2026-07-24 (Opus 4.8, thinking)

**Inputs:** 40 on-device Android screens (light mode, real data, mixed EN chrome + HE user
content) across passes 1–4, saved under `UI-snapshots/pass1-first-run…pass4-coach-chat/`,
plus 9 live-site captures under `UI-snapshots/pass5-website/`. RTL judged from HE rules,
session titles, meal names, and coach replies. No dark-mode shots (deferred, per constraints).

### Top-level verdict

Healthings is **functionally ahead of its visual craft**. The data work is genuinely strong —
Lab Results cholesterol trends, glucose-vs-heart-rate with workout annotations, and the
energy-balance panels build real clinical trust. The strip IA is sound.

The biggest lever is **perceived quality + hierarchy**, not features. Three drags: (1)
**emoji-as-iconography** everywhere (mentors, water, PDF, pointing finger) fights
"clinical-but-warm" and reads prototype-y; (2) the dashboard drifts into **card-soup** —
a dozen equal-weight white cards where nothing signals priority; (3) **first-run friction**
— progress denominator that grows as you answer and Yes/No hidden below the fold. Fixing hierarchy + a real icon set + tightening
Quick Start moves it from "capable alpha" to "premium health product" with **no change to
stored data, units, or clinical numbers** — all presentation.

### Findings (P0 → P2)

Format: ID · severity · where · problem · recommendation · risk/effort.

**P0 — broken / confusing / inaccessible**

- ~~F1 · "Refreshing SIM data" toast~~ — **WITHDRAWN 2026-07-24**: this is the phone's eSIM
  status message, not the app. Not an app issue.
- **F2 · QS progress denominator changes mid-flow** — header "X of N"; N grows 11→12→13 as
  user answers Yes. Destroys the progress bar's job; looks like a glitch. → Stable total (max
  possible) or drop numeric "of N", keep dot bar. Logic-only. **M**
- **F3 · Trend chart y-axis labels collide** — 4 differently-scaled series on one plot; left
  axis numbers overlap ("77.0/42.7", "-4.1/3.9"). Unreadable, looks broken. → Per-series mini
  panels (copy the ENERGY sparkline stack) or index to % change with one axis. Values
  unchanged. **M/L**

**P1 — weak, hurts trust / conversion**

- **F4 · Yes/No hidden below the fold (QS scale/watch/CGM)** — hero + heading + body push the
  decision off-screen; the "Tap Yes or No 👆" hint is the tell users got stuck. → Shrink hero
  on decision steps; pin Yes/No above the sticky footer; drop the finger hint. RTL/long-text
  safe as fixed row. **M**
- **F5 · Language gate: two disconnected language controls** — a 2-col text list of "Select
  language" translations up top (looks tappable, isn't) + the real flag tray at the bottom,
  big dead gap between. → One control: grid cells = flag + native name; one localized header.
  Fit 10 cells + RTL names (2×5). **M**
- **F6 · Dashboard card-soup / flat hierarchy** (`DashboardScreen.tsx`) — ~10 equal-weight
  white cards, differentiated only by low-contrast gray labels; no triage. → Weight tiers:
  metrics + AI chat + Food Log primary; Glucose/Trend/Profile/Labs secondary compact rows;
  per-strip icon so scanning is by shape. Structural, no data change. **L**
- **F7 · Emoji as the icon system** — mentors 🩺🥗💪, water, PDF, finger, Gallery 🖼️. OS-variant,
  inconsistent, undercuts credibility; biggest perceived-quality drag. → One line-icon set
  (Lucide/Phosphor) + small custom mentor avatars; emoji only inside chat content. **L**, high payoff
- **F8 · Chat input has too many cryptic buttons** — Camera, ↑, ↓, Clear, ↗, Send; the
  arrows are unlabeled/unguessable. → Keep Camera + text + Send; collapse scroll/expand/clear
  into overflow or remove. **M**
- **F9 · "Refresh my data" only at very bottom** — main sync action below a long scroll. → Add
  pull-to-refresh and/or a compact header refresh. **M**
- **F10 · Off-brand purple Gallery tile** (Log Meal) — purple exists nowhere else; arbitrary
  color-coding. → Brand-consistent tiles differentiated by icon, not hue. **S**
- **F11 · Low-contrast strip labels & secondary text** — light-gray small-caps on white likely
  fail AA (needs 4.5:1); these are the primary wayfinding labels. → Darken to pass AA
  (~#5b6470 or darker). Token change. **S**

**P2 — polish**

- **F12 · Header redundancy** — "Quick Start" title + "Quick Start · 3 of 11" subtitle repeats;
  step 1 shows step name, later steps drop it. → Subtitle = step name + count, consistently. **S**
- **F13 · Mixed-direction HE user content in EN chrome** — Rules/Targets/session summaries show
  Hebrew left-aligned; bidi punctuation looks off. → Right-align detected-RTL directive/rule
  text even when chrome is English (matches language-policy). Edit-item Name already does this
  right. **M**
- **F14 · Dashed borders on primary actions** — Meal / Add water use dashed (a "placeholder/add"
  convention), making primary actions feel secondary. → Solid for active; dashed only for empty
  "Add". **S**
- **F15 · Two delete concepts in Edit Meal** — per-item "Delete" + footer pink trash. → Clarify
  footer = delete whole meal. **S**
- **F16 · Expand/collapse affordance inconsistent** — collapsed ">" vs expanded top "^". → Unify. **S**
- **F17 · "0/4 actions" unexplained** (AI-chat badge). → Label ("0 of 4 coach tips"). **S**
- **F18 · Brand wordmark eats top-of-fold** on every dashboard load. → Slim to compact header. **S**
- **F19 · Website: sparse desktop help + jargon H1** — help is a narrow centered column with big
  empty desktop margins; landing H1 "A full metabolic OS" is jargon for patients. → Widen/format
  help; lead with patient value prop. **M**
- **F20 · CGM blood-drop illustration** reads alarming/heavy. → Soften. **S**

### Design-system recommendations

- **Type scale (codify existing):** Display 28/34 · H1 22/28 · H2 18/24 · Body 16/24 · Label
  13/16 caps · Caption 12/16. Cap hero headings at 2 lines.
- **Spacing tokens:** 4/8/12/16/24/32. Card pad 16, inter-card gap 12, section gap 24. One rhythm.
- **Color/contrast:** Lock to navy + teal + one blue accent + semantic (green/red/amber); retire
  purple. Darken labels/secondary to AA. Fixed documented chart color map
  (weight/fat/muscle/visceral/glucose/HR) reused everywhere.
- **5 component rules:** (1) Strip = icon + label + summary + one chevron affordance. (2) Primary
  = solid, secondary = outline, add/empty = dashed — never mix. (3) One line-icon set; emoji only
  in chat. (4) Decision steps keep Yes/No above the fold, fixed row above sticky footer. (5) RTL
  user content auto-aligns by detected script regardless of chrome language.

### Suggested implementation sequence (shippable batches)

- **Batch A — quick trust wins (all S):** F11, F10, F14, F12, F16, F17. Low risk, immediate lift.
- **Batch B — first-run polish:** F2, F4, F5.
- **Batch C — hierarchy + identity:** F7 (icon set) → F6 (dashboard tiers) → F18. Biggest leap;
  icon set first (F6 depends on it).
- **Batch D — data-viz + chat:** F3, F8, F9.
- **Batch E — content/web/RTL:** F13, F19, F15, F20.
