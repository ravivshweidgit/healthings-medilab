## Prompt 54 — Local-first clinic relay (ephemeral snapshot + rules mailbox + stateless chat)

**Status: backlog — app **Share** button shipped + phone-tested 2026-07-03; server relay pending**  
**Priority:** **next** (after `done/prompt53`)  
**Builds on:** `prompt49.txt` · `done/prompt51.txt` (phone rules history) · clinic refresh snapshot flow

---

### Problem

Shipped clinic sync stores **full patient exports in Postgres** (`sync_blobs`) and **persistent overlays** (`clinic_patient_overlays`, `clinic_patient_rules_history`). That contradicts local-first, `privacy.html`, and `be-04` intent. Regulators and users expect: **phone = source of truth**; server only **relays what the patient chose to share while linked**.

---

### Product decisions (locked 2026-07-03)

| # | Rule | Detail |
|---|------|--------|
| **1** | **Snapshot relay, cleared on revoke** | Patient share/refresh → gzip export in **server heap `Map`** (or single slot), not durable `sync_blobs`. **DELETE** on share revoke (+ optional TTL while linked, e.g. 8h). |
| **2** | **Pending My Rules mailbox** | Clinic saves rules → `pendingRules` on relay. Phone polls → `saveUserRulesWithHistory({ source: 'clinic' })` → **null** pending. Poll when null → no-op. **No** `clinic_patient_overlays.rules_json`. |
| **3** | **Clinic mentor chat not on server** | Browser holds `thread[]`; each `POST` sends `priorMessages`. Server returns Gemini reply only. Refresh/close tab → lost (intentional). **No** `chat_json` DB. |
| **4** | **Patient manual Share (app)** | On **Data sharing** strip, each approved clinic row: **Share** (upload snapshot to relay) + **Revoke**. Share places gzip on server **waiting for clinic to collect** — remains while link is approved even if patient **closes the app**. Clinic collects via portal **Refresh snapshot** (or reads relay directly). Auto-upload on clinic request + on first approve still applies. |

**Also:**

- **My Rules history** — phone only (`user_rules_history_v1`); **remove** `clinic_patient_rules_history` + portal server history UI.
- **Revoke hook** — purge relay snapshot + pending rules + `sync_update_requests` for patient.
- **`privacy.html`** — default on device; optional relay while linked; deleted on revoke; clinic chat not stored.
- **Gemini on server** — still processes snapshot/priorMessages in flight; disclose in policy.

**Regulatory positioning (wellness alpha):** not SaMD; optional patient-directed share; no longitudinal server medical record.

---

### Architecture

```
Phone (source of truth)
  Share (manual) ──► POST /v1/sync/upload ──► relay.set(patientId, snapshotGzip, summary)
  clinic refresh ──► sync_update_request ──► phone auto-upload when app open (unchanged)
  poll rules     ──► GET consume pendingRules ──► apply + null

Clinic portal
  view patient   ──► GET relay snapshot (approved share only)
  Refresh snap   ──► requests phone OR reads relay if patient already tapped Share
  save rules     ──► PUT pendingRules (mailbox)
  chat           ──► POST { message, priorMessages } → { reply } (stateless)

Revoke share     ──► relay.delete(patientId) + clear pending + sync requests
```

**App UX (Data sharing strip — `ClinicLinkStrip`)**

| Control | Behaviour |
|---------|-----------|
| **Share** | Patient taps → `shareClinicExport('90d')` → relay slot updated; show last-shared time + version. Works with app closed afterward (blob on server). |
| **Revoke** | Purge relay + end whitelist (existing). |
| Status line | `Last shared: … (vN)` or `No upload yet — tap Share or wait for clinic refresh` |

**Alpha note:** Until relay ships, `POST /v1/sync/upload` still writes `sync_blobs`; UI and API shape unchanged so relay swap is server-only.

**Storage:** in-memory `Map` per `patientId` on single VPS (alpha). Redis + TTL when multi-instance.

**Stop using:** durable `sync_blobs` writes, `clinic_patient_overlays`, `clinic_patient_rules_history`.

### API changes

| Endpoint | Change |
|----------|--------|
| `POST /v1/sync/upload` | Write relay, not Postgres |
| `GET /v1/sync/latest` | Read relay; 404 if revoked/expired |
| `POST /v1/shares/:id/revoke` | Call `purgePatientRelay(patientId)` |
| `PUT .../rules` | Set `pendingRules` only |
| `GET /v1/clinic/overlays` or new `GET .../pending-rules` | Consume-on-read pending rules |
| `POST .../chat` | Accept `priorMessages[]`; no DB append |
| **Remove** | `GET .../rules/history`, server rules restore on portal |
