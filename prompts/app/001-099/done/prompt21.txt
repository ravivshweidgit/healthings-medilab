## Persistence architecture (shipped — do not rebuild)

### Principle
```
Adapters (HC, CSV)  →  sync*()  →  merge  →  local store  →  UI + mentors
```

- **Store key:** `healthings:lastMetrics` (`CachedHealthMetrics`)
- **Raw fields:** `glucose[]` (all merged samples) + `cgmSessionStarts[]`
- **View layer:** `prepareGlucoseSeries()` → filtered chart series + `cgmStatSummary`
- **Never wipe on failed sync:** `syncCgmStore()` returns cached store when HC unavailable

### Services

| Layer | File | Role |
|-------|------|------|
| CGM store | `CgmPersistenceService.ts` | `loadCgmStore`, `saveCgmStore`, `syncCgmStore`, `mergeImportedGlucoseIntoStore`, `loadCgmViewFromStore` |
| Merge + filters | `healthMetricsCache.ts` | `mergeGlucoseTimePoints`, `prepareGlucoseSeries`, `filterGlucoseToDayKeys` |
| Unified facade | `HealthPersistenceService.ts` | `loadHealthPersistence()` / `syncHealthPersistence()` (CGM + Withings) |
| Dashboard hook | `useHealthData.ts` | Bootstrap from store → background `syncCgmStore`; `withGlucoseSyncLock` on import/refetch |
| Mentors / reviews | `ReviewService.ts` | `syncCgmStore()` then `loadCgmViewFromStore()` before `buildPeriodReviewBlock` |

### Merge rules (in `CgmPersistenceService`)

| Operation | Merge order | Winner on duplicate instant |
|-----------|-------------|----------------------------|
| **Sync** (`syncCgmStore`) | `[store, HC]` | HC |
| **CSV import** (`mergeImportedGlucoseIntoStore`) | `[store, HC, CSV]` | CSV |

Both paths **persist merged raw** to AsyncStorage before updating the chart view.

### Mentor CGM path (current)

Chat and coach do **not** rely on React `coachContext.glucoseHistory` alone:

1. Every turn: `buildPeriodReviewBlock({ days: 2 })` (or wider on `/7`, `/30`)
2. Block builder calls `syncCgmStore()` + `loadCgmViewFromStore(appGlucose)`
3. Injects `GLUCOSE & FOOD IMPACT`, per-day `MEAL GLUCOSE`, and (today+yesterday)
   `CGM ALL READINGS` raw series

Dashboard still builds `todayMealGlucoseDetail` via `buildGlucoseMentorContext()` for CGM
rule flags; **numbers** in chat come from PERIOD REVIEW + persistence.

## PART C — Fresh CGM in chat coach refresh (`ChatScreen.tsx`) — **mostly mitigated**

> **Status (2026-06-17):** Persistence + prompt23 closed the main gap. `buildPeriodReviewBlock`
> calls `syncCgmStore()` every chat/coach turn, so mentors usually see post-Sync glucose even
> when dashboard `coachContext.glucoseHistory` is stale.

**Remaining gap (safety net only):**

`buildFreshContext()` reloads meals/macros/rules but **not** `glucoseHistory` /
`todayMealGlucoseDetail`. If `buildPeriodReviewBlock` fails (`.catch(() => '')`), fallback
rules in `buildCgmMentorRules` still see stale `context.glucoseHistory`.

Fix (small):
```ts
// Inside buildFreshContext():
const cgm = await loadCgmViewFromStore();
const meals = await getTodayMeals();
return {
  ...context,
  glucoseHistory: cgm.glucose,
  todayMealGlucoseDetail: buildGlucoseMentorContext(
    meals, cgm.glucose, cgm.cgmSessionStarts, cgm.cgmStatSummary,
  ),
  // ...existing meal/macro reload...
};
```

Optional: call `syncCgmStore()` here instead of read-only `loadCgmViewFromStore` if we want
chat ↻ to trigger HC pull (heavier; prefer read-only safety net).

Coach ↻ refresh should cite updated MEAL GLUCOSE / PERIOD REVIEW after dashboard Sync
without closing chat — verify on device after fix.
