## Prompt 60 — Optional cloud backup (opt-in, purge on off)

**Status: shipping 2026-07-08** · phone test pending · **requires API deploy + `npm run migrate`**

**Builds on:** `LocalBackupService` · `be-04` (alpha: HTTPS + ACL, not E2E yet)

---

### Problem

Data is local-first; users who lose a phone need disaster recovery. Optional cloud backup must be explicit opt-in; off must purge server copy. Auto-upload must not let a thin/empty phone wipe a richer cloud copy.

---

### What ships

| Layer | Change |
|-------|--------|
| **Server** | `user_cloud_backups` (+ fingerprint JSONB, previous blob columns); `GET/PUT/DELETE /v1/account/backup` + status |
| **App** | Account → Cloud backup toggle, Back up now, Restore |
| **Payload** | Local export shape, gzip, **no Withings tokens** |
| **Off** | `DELETE` purges current + previous; phone unchanged |
| **Richness guard** | Fingerprint (`earliestDay`, `mealDays`, `byteSize`, …). Phone may replace cloud only if ≥ as rich. **409** + Force replace / Restore UI |
| **Previous blob** | On successful overwrite, old payload moved to `prev_*` (one generation) |
| **Daily auto** | ~once per 24h when opted in + app active (`maybeRunOpportunisticCloudBackup`) |

---

### Overwrite rules (summary)

Block if phone is emptyish vs rich cloud, phone `earliestDay` newer than cloud, **fewer meal days than cloud**, or size &lt; 50% of cloud — unless `force: true`. Never fewer meals.
