## Prompt 40 — Recipe & meal plans (kitchen units, viewer, slash commands)

**Status: planned** — Item 3 from dashboard UX batch (after prompt39 food log history).

**User thoughts (2026-06-19):** export daily/weekly plans; slash commands `/eat` `/daily` `/weekly`; foods I like / don't like; natural language **"בנה את השייק מאתמול בערב"** (rebuild from food log history).

### Problem (user-reported)

When working with **Nutritionist 🥗** in chat:

1. **Shake / recipe help** — user needs **kitchen measures** (tsp, tbsp, scoop, cups, unit count), not only grams. Grams are fine for bulk items (salmon 150g); impractical for powders, spices, nut butter, whey scoop.
2. **Full-day / week menu** — user wants a **readable plan view**, not long prose in the chat bubble. Chat currently shows plain `Text`; model sometimes leaks `<br>`, `<i>`, other HTML — `normalizeMentorChatText` strips some tags but chat is not a document viewer.
3. **"What should I eat now?"** — needs a quick suggestion grounded in **remaining macros today**, time of day, preferences, and history — not a wall of text.
4. **Food preferences** — no structured **likes / dislikes** today (only My Rules constraints). Plans should respect "I love salmon, hate cottage cheese."
5. **Rebuild from log** — same idea as prompt39 food log, but in **nutritionist chat**: "בנה את השייק מאתמול בערב" → recipe card with kitchen units, copied from logged meal.
6. User is **unsure of exact UX** — this spec proposes options and a recommended path.

### Design principle

> **Chat = conversation. Viewer = document.**

Same pattern as **MacroProposalCard** (`/macros`): short chat line + structured card / full-screen viewer — not HTML in the bubble.

## Slash commands (nutritionist tab only)

Mirror `/macros` pattern: nutritionist tab, structured JSON pipeline, short chat intro + card.

**Commands accept trailing text** — slash sets the *pipeline*; everything after the command is the *user hint* (same message, no second prompt).

```
/eat shake from last evening
       └────────────────────── hint (parsed + passed to Gemini + history matcher)
```

| Command | Meaning | Output |
|---------|---------|--------|
| `/eat` | What should I eat **right now**? | `RecipePlan` — sized to **remaining macros today** + time of day |
| `/eat chicken salad` | Eat now, biased by hint | Same |
| `/eat shake from last evening` | Rebuild / suggest that meal **now** | History match → `RecipePlan` card (kitchen units) |
| `/eat השייק מאתמול בערב` | Hebrew hint on same command | Same |
| `/daily` | Plan my **whole day** | `DayPlan` card (today) |
| `/daily low carb` | Day plan with modifier | `DayPlan` + constraint in hint |
| `/daily like yesterday` | Day shaped like prior log day | `DayPlan` + food log history in context |
| `/weekly` | Plan my **week** | `WeekPlan` card |
| `/weekly no fish` | Week plan respecting hint | `WeekPlan` + dislikes / hint |
| `/recipe protein shake` | Force single recipe (no "now" sizing) | `RecipePlan` |
| `/אכול` `/יום` `/שבוע` | Hebrew command aliases | Same; hint may be Hebrew or English |

**Parsing (code):**

```ts
// Returns { command: 'eat' | 'daily' | 'weekly' | 'recipe', hint: string }
parseMealSlashCommand(text: string): MealSlashCommand | null

// Examples:
// "/eat shake from last evening" → { command: 'eat', hint: 'shake from last evening' }
// "/daily"                       → { command: 'daily', hint: '' }
// "/weekly no fish"              → { command: 'weekly', hint: 'no fish' }
```

When `hint` references history ("last evening", "yesterday", "usual", "מאתמול", "הרגיל"):
→ run **history matcher first** (prompt39 block), then `generateRecipePlan` / day plan with matched entry as template.

When `hint` is empty:
→ `/eat` uses remaining macros + time; `/daily` / `/weekly` use targets + preferences only.

**`/eat` vs `/recipe`:**

| | `/eat` | `/recipe` |
|---|--------|-----------|
| Sizing | Fits **remaining today** (may scale servings) | Full recipe as written |
| History hint | "same shake as last night" → rebuild + optional scale | "shake from last evening" → faithful copy |
| Use case | "What now?" | "Give me the recipe" |

**`/eat` context (auto-injected):**

- Parsed `hint` string (if any)
- Local time + meal slot (breakfast / lunch / dinner / snack)
- `macroTarget` vs **eaten so far today** (remaining P/C/F/kcal)
- Food preferences (likes / dislikes)
- Food log history (recent meals, frequent patterns — prompt39 `formatFoodLogHistoryForMealAi`)
- My Rules + labs (hard constraints)

**Wrong tab:** same hint as `/macros` — "available on Nutritionist 🥗 tab only."

Natural language **without** slash still works via intent detection; commands force the structured path reliably. **Prefer slash + hint** when user wants both behavior and specificity in one message.

## Rebuild from food log ("בנה את השייק מאתמול בערב")

**Same history engine as prompt39**, wired into nutritionist recipe generation:

```
User: "בנה את השייק מאתמול בערב"
  → getRecentMeals(14) + formatFoodLogHistoryForMealAi()
  → generateRecipeFromHistory()  // match entry → RecipePlan JSON
  → enrich with kitchen units (scoop/tsp) where grams-only in log
  → RecipeCard + viewer
```

| Surface | Action |
|---------|--------|
| Food log modal | **Add** meal to log (`analyzeFood` + history) |
| Nutritionist chat | **Build** recipe card for viewing / re-cooking (`generateRecipePlan` + history) |

Prompt rule: when history match found, **copy items/macros** from log; add `amount_display` kitchen units for small ingredients; cite matched date/time in card subtitle.

Examples (slash + hint **or** plain language):

- `/eat shake from last evening` → rebuild evening shake, sized for now if needed
- `/eat` (no hint) → AI picks from remaining macros
- "בנה את השייק מאתמול בערב" → same as above without slash (intent `rebuild_from_log`)
- `/recipe shake from last evening` → faithful recipe card, no "remaining kcal" scaling
- "same as my usual chicken meal" → FREQUENT MEALS pattern → recipe card
- `/daily like yesterday` → day plan modeled on prior log day

## Food preferences — likes & dislikes (40f)

**Gap today:** `UserRules` = constraints (keto, kidney, cholesterol). No explicit **preference** list.

**Proposed:** `FoodPreferences` in profile (separate from medical rules):

```ts
type FoodPreferences = {
  likes: string[];      // "salmon", "almonds", "שייק חלבון"
  dislikes: string[];   // "cottage cheese", "כבד עוף"
  updatedAt: string;
};
```

**UI (My Profile or Food section):**

```
┌─ Foods I like ────────────────────────┐
│ salmon · almonds · protein shake  [+] │
├─ Foods I avoid ───────────────────────┤
│ cottage cheese · liver            [+] │
└───────────────────────────────────────┘
```

- Free-text chips + optional AI parse from chat: "I hate cottage cheese" → offer to save to dislikes
- **Optional assist:** infer candidates from food log (frequent = like candidate; never repeated after one try = weak dislike signal) — user confirms, never auto-write
- Injected into: `/eat`, `/daily`, `/weekly`, recipe generation, nutritionist chat USER DATA block

**Not** mixed into My Rules medical constraints — preferences are soft (avoid when possible), rules are hard.

## Recommended architecture (Option A)

### 40a — Recipe card (shake / single meal / `/eat`)

**Trigger** (nutritionist tab):

- Slash: `/eat`, `/recipe`, `/אכול`
- Intent: `recipe` — shake, smoothie, recipe, מתכון, שייק, איך להכין
- Intent: `rebuild_from_log` — בנה את ה… מאתמול, same as last night, השייק מאתמול
- Intent: `day_plan` — full day, תפריט ליום (or `/daily`)
- Intent: `week_plan` — weekly, תפריט לשבוע (or `/weekly`)

**Flow:**

```
User message
  → detectMealPlanIntent()  // slash > rebuild > week > day > recipe > eat-now
  → load: macroTarget, today eaten, foodPreferences, foodLogHistory
  → generateRecipePlan() | generateDayPlan() | generateWeekPlan()
  → ChatMessageUI { text: short intro, recipeCard?, dayPlanCard?, weekPlanCard? }
  → RecipeViewerModal / DayPlanViewerModal / WeekPlanViewerModal
```

**JSON schema — `RecipePlan`:**

```json
{
  "title": "Protein shake",
  "title_local": "שייק חלבון",
  "servings": 1,
  "items": [
    {
      "name": "whey protein",
      "name_local": "אבקת חלבון",
      "amount_display": "1 scoop",
      "amount_display_local": "1 סקופ",
      "grams": 30,
      "kcal": 120,
      "protein_g": 24,
      "carb_g": 3,
      "fat_g": 1,
      "fiber_g": 0
    }
  ],
  "steps": ["Blend 30 seconds."],
  "total_kcal": 280,
  "total_protein_g": 32,
  "confidence": "medium"
}
```

**Unit rules (prompt + code validation):**

| Food type | Primary display | Grams |
|-----------|-----------------|-------|
| Powders (whey, cocoa, cinnamon) | scoop / tsp / tbsp | secondary, smaller text |
| Liquids (milk, oil) | cup / tbsp / ml | optional secondary |
| Countable (egg, banana, slice) | count + size | weight in parentheses |
| Proteins / fish / meat | **grams** (150g salmon) | primary |
| Vegetables (bulk) | grams or cup | either |

Prompt line: *"Never give only grams for amounts under ~30g that users measure with spoons/scoops unless they asked for grams."*

**Actions:**

- **Log as meal** → map `items[]` to `FoodItem[]` → open `FoodLogModal` pre-filled (recommend over silent save)
- **Share** → HTML or plain text via export helpers (40e)
- **Save recipe** → optional library (40c)

1. Extend `normalizeMentorChatText` to strip `<i>`, `<b>`, `<em>`, `<strong>` (or map to plain text).
2. Keep chat prompt rule: **plain prose in `response`** — recipes/day plans must use structured JSON path, not HTML tables in chat.
3. `MessageBubble` today renders `msg.text` only — structured cards render beside it (like `macroProposal`).
